# Architecture: Sync Service

> Generated by Claude Code on 2026-11-02. Review before merging.

## Overview

The sync service keeps local vaults and the remote store consistent. It is split into **three** layers:

1. **Watcher** — listens for file system events and debounces them (`200ms`).
2. **Differ** — computes block-level diffs using `similar`.
3. **Uploader** — batches changes and retries with exponential backoff.

```mermaid

  W[Watcher] --> D[Differ]
  D --> U[Uploader]
  U -->|ack| W
```

## Data model

| Field | Type | Notes |
|---|---|---|
| `id` | `TEXT` | ULID, primary key |
| `path` | `TEXT` | relative to vault root |
| `hash` | `BLOB` | blake3 of normalized content |
| `mtime` | `INTEGER` | unix millis |

### Invariants

- Every block has exactly one owner.
- A block's `hash` changes iff its normalized text changes.
  - Normalization strips trailing whitespace.
  - Line endings are converted to `\n` before hashing.
- Deleted files keep a tombstone for 30 days.

### Step 3: differ

```rust
pub fn diff_blocks(old: &[Block], new: &[Block]) -> Vec<Change> {
    let ops = similar::capture_diff_slices(Algorithm::Patience, old, new);
    ops.into_iter().flat_map(Change::from_op).collect()
}
```

Edge cases to handle:

* Moved blocks should be reported as a move, not delete + insert.
